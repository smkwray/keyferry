# Tailscale discovery

Keyferry uses the same direct-peer shape as MeshElf. Every normal Windows/macOS installation runs
its own daemon. The controller asks the local Tailscale client which peers are online and probes
their Tailscale IPv4 addresses directly:

```text
controller -> http://<peer-tailscale-ip>:18043             discovery hint
controller -> owner-mTLS://<peer-tailscale-ip>:18044       authenticated control
```

The unauthenticated probe reveals only a bounded installation identity. It does not prove that the
peer is trusted or that it currently controls a stick. The controller opens the control route only
with its own owner-issued installation certificate, authenticates the peer under the same owner CA,
then requires a fresh controller-specific proof generated by the live stick. A computer name,
Tailscale address, tailnet membership, cached pairing, or old gateway record grants no authority.

No Tailscale Serve route, application capability, tag, or per-machine Keyferry policy edit is
required when the owner's tailnet permits ordinary peer connectivity. A deliberately restrictive
tailnet can still deny the connection; Keyferry reports that as unreachable and cannot override an
administrator's network policy.

The universal installers place one unique installation credential under the current user's private
Keyferry state directory and supervise `keyferryd --installation <directory>`. The daemon starts its
loopback API and nearby Bluetooth gateway even while Tailscale is absent. It periodically discovers
the current local Tailscale IPv4 address, binds the two owner endpoints only to that address, and
rebinds if the address changes.

Issue each computer separately from the encrypted portable owner kit:

```text
keyferry-pairing issue-installation --owner-kit <owner-kit.json> --output <installation-directory>
```

The passphrase is read from standard input, never from arguments. An ordinary installation contains
only its own private key, certificates, and device-scoped derived secrets. It does not contain the
owner signing key or device recovery secret. Copying one installation directory to several machines
is prohibited because it destroys per-installation identity and revocation.

The old shared-bearer `gateway.json` and named Windows gateway installer are legacy v1 artifacts;
they are not part of roaming-v2 deployment. Do not expose either owner port on LAN or a wildcard
interface, use Funnel, or treat a successful discovery response as permission to arm or type.
